# 交付前自我檢查清單

**在交付之前(`present_files` 或 `Artifact` 發布),逐項對照這份清單。** 每一項都要能明確回答「有做到」,不能靠感覺。這份清單存在的理由:先前實測時反覆出現的問題,不是 Claude 不知道標準,而是標準寫成散文之後每次都會漏掉其中幾項。逐項打勾才擋得住。

任何一項答不出「有」,就回去補,不要先交付再說。

---

## 零、硬擋清單(先跑這 15 項,任一項沒過就不能交付)

底下的完整清單有 210 項,全部重要,但**重要程度不同**。這一節是「沒做到就等於交出一份錯的東西」的部分,先跑這 15 項,再往下跑完整清單。

**一次交付不會跑到 210 項。** 第七節(B5 列印手冊 33 項)與第八節(A4 精簡版 17 項)**只在做那一份衍生版時才跑**;交付詳細版實際要跑的是 160 項。

分兩級的理由:清單太長會被跳著看,那就退回散文標準的老問題。把最不能錯的先隔離出來,至少擋得住災難級的錯誤。

**這 15 項在下面的分類清單裡會再出現一次,那是刻意的,不是重複。** 它們重要到值得檢查兩遍。

- [ ] **目的地**是使用者在這次問卷裡親口確認的,不是從上下文推來的
- [ ] **固定錨點**問過了,而且拿到明確答案(包括明確的「沒有」)
- [ ] **事由分支題組**問完了(商務出差有問到會議時間地點;接待貴賓有問到貴賓班機與接待窗口)
- [ ] **Step 2.5 的兩件事在同一則回覆裡都做了**:最終確認清單 + 詢問是否存檔
- [ ] 每一個排入的地點都通過**營業時間與休館日查核**,查不到的有標註並附已確認營業的備選
- [ ] **逐行驗算過**:每一行的結束時間 ≤ 下一行的開始時間,用手算過不是目測
- [ ] (入口 B2:使用者拿來一份自己的行程)**逐項確認過哪些是真錨點、哪些只是草案** —— 把草案當成不可動的錨點,整份行程會繞著一個假錨點排
- [ ] 班機、飯店、店家、時刻、天氣**沒有任何一項是憑空捏造或錯誤呈現的** —— 包含:沒有放查不到的店家、沒有把歷史氣候平均寫成預報
- [ ] 時間**精確到分鐘**,沒有「上午/下午/傍晚」
- [ ] 每日活動數量**對得上使用者選的步調**(緊湊 5-6、適中 4-5、悠閒 2-3)
- [ ] 沒有任何地方只標「**待補**」就斷在那裡,每個未確定項都有具體的下一步動作
- [ ] **使用者說「這趟最想達成的一兩件事」真的排進去了**,而且給了足夠時間 —— 漏掉這個,其他每一格都對也救不回來
- [ ] **問卷收集到的限制逐項回核過**(飲食、無障礙、體力、年長者、兒童、保密、語言、價位、其他禁忌),而且核對結果寫進文件裡了 —— 問了限制卻沒拿出來對,等於問了等於沒問
- [ ] 存檔與文件裡**沒有健康/身心障礙/種族/宗教/政治立場等敏感類別**,醫療資訊已轉為中性描述
- [ ] **只交付詳細版一份**,沒有同時做任何衍生版(B5 列印手冊、A4 精簡版都是內容定案後的另一個階段)

以上 15 項全過,再往下跑完整清單。完整清單裡沒做到的項目,如果決定不補,要在交付訊息裡向使用者說明是哪幾項、為什麼。**不可以默默略過。**

## 一、問卷完整性

- [ ] 目的地是使用者在這次問卷裡**親口確認**的,不是從對話上下文、先前範例或假設情境推來的
- [ ] 天數/日期是使用者明確給的
- [ ] **固定錨點問過了**,而且拿到了明確答案(包括使用者明確說「沒有」)
- [ ] 事由問過了,而且**對應的 A-2 分支題組問完了**(商務出差有問到會議時間地點;接待貴賓有問到貴賓班機與接待窗口)
- [ ] 同行者身分角色不同時,偏好類問題(艙等、房型、步調、飲食、緊急聯絡人)是**逐位確認**過的,不是套用同一組答案
- [ ] 【條件】題的條件成立時都問了,不成立的都跳過了(沒有硬問無關題目把使用者問到放棄)
- [ ] Step 2.5 的兩件事**在同一則回覆裡**都做了:最終確認清單 + 詢問是否存檔
- [ ] 全程對使用者說話**沒有用內部機制的詞彙**(記憶目錄、`Glob`、`memory_list`、`places_search`);具體檔案路徑照講,要避免的是機制名稱
- [ ] 告知問卷輪數時說的是「**大約** 5-6 輪,可能多一兩輪追問」,沒有講死一個數字
- [ ] 行程文件裡每一項「未提供、採預設」的資訊,都在最終確認清單裡向使用者標示過
- [ ] **用餐時間偏好與每日時間邊界拿到的是具體時刻**(最早幾點出門、最晚幾點回飯店、午晚餐幾點),不是「早出晚歸」這種無法換算成時刻的分類
- [ ] (全程包車或有固定座車)**包車時數、司機可用時段到幾點、超時怎麼計費**問了
- [ ] (需要車輛)車型與座位需求問了(乘車人數 + 行李件數 → 幾人座或幾台車)
- [ ] (國外或兩岸)**目的地專屬證件**的辦理狀態與效期問了(台胞證、ESTA、ETA、電子簽)
- [ ] **H 類交付對象**問了(這份行程要給誰看),而且文件的寫法對應了答案
- [ ] Step 2.5 做了**可行性檢查**,發現的矛盾都攤開給使用者並附了兩三個具體解法
- [ ] (多城市)城市順序、各城停留晚數、城際交通方式問了
- [ ] (入口 B2:使用者拿來一份自己的行程)既有內容**逐項核對過**名稱精確度、營業時間相容性、時間與交通是否對得上、地址與現況;核對出的錯誤都明確列出來了,沒有默默修掉
- [ ] (入口 B2)**逐項確認過哪些是真錨點、哪些只是草案**,沒有把草案當成不可動的錨點
- [ ] (Claude Code)問入口之前**先列過 `itineraries/`**;裡面有既有檔就帶著檔名問,沒有預設使用者是要排新的
- [ ] (入口 B1:改這個 skill 自己產出過的手冊)**整份讀過才改**(速查總表、訂位狀態追蹤表、備案的替換對應、費用分項),而且分清楚這次是「換內容」還是「只加圖/只出列印版/只改排版」—— 後者沒有藉機重排一遍行程
- [ ] (入口 B1)依製表日期重查過**會過期的欄位**(營業時間、休館日、票價、班次、價格),改動走過 **Step 7 的八個同步點**,並存成新版號檔名、沒有覆蓋舊檔

## 二、排程正確性

- [ ] 固定錨點**優先落位**,其他活動繞著它排;錨點在行程上標為不可調整
- [ ] 每一個景點/餐廳/店家/展館都通過了**營業時間與休館日查核**(確認過行程當天那個星期幾營業、時段覆蓋安排的時間)
- [ ] 查不到營業時間的項目,標註了「未能確認、建議出發前確認」**並附上一個已確認營業的備選**
- [ ] 地點之間的交通時間是實際查過的,前一項結束時間 + 交通時間 ≤ 下一項開始時間(自己重算一遍,不要目測)
- [ ] 跨時區行程的時間都標了當地時間;跨日抵達的班機標了 `+1`
- [ ] **抵達時刻用的是航空公司公布的當地時刻**,不是自己用「起飛時間 + 飛行時數」加算的
- [ ] (目的地資料稀少時)**明確告訴使用者查證的覆蓋程度**,沒有為了湊密度編出查不到的地點
- [ ] 班機/飯店/店家資訊都是查證過的真實資料,沒有任何憑空捏造的班號、店名、時刻或天氣
- [ ] 查不到的店家**換掉了**,沒有放一個查不到的店然後標「待確認」把問題丟回給使用者
- [ ] 兩個來源衝突時**在文件裡標出來了**,沒有自己挑一個就算
- [ ] 來源超過一年的營業時間或票價,標了「資訊日期較舊,建議出發前確認」
- [ ] **天氣用對了**:行程在 10-14 天內才用預報;一個月以上用的是該月份歷史氣候平均,而且文件裡明確標示「這是歷史平均不是預報,出發前一週請再查」
- [ ] **用餐時段是在挑景點之前先落位的**,沒有出現「14:20 吃午餐」或用 60 分鐘排套餐制餐廳這種被擠壓的結果
- [ ] **抵達日**按實際可用時間排(扣掉入境通關、提領行李、進市區車程、check in),沒有當成完整一天
- [ ] **離開日**從起飛時刻往回推(國際線 2.5-3 小時前抵達機場 + 車程緩衝 + 退房),活動選的是可以隨時中斷的
- [ ] 用的是**最後入場時間**,不是營業結束時間(多數館的最後入場早 30-60 分)
- [ ] 相鄰項目之間的移動**單程不超過 30-40 分鐘**(進出機場與跨城移動除外);超過的有檢查過是不是一天塞了兩個區域
- [ ] **錨點前留了緩衝**,而且緩衝對應風險(一般 15-30 分、要排隊或核驗 30-60 分、會議與班機再加)
- [ ] 各項目的**停留時間對得上類型**(大型博物館 90-150 分、小型館 60-75 分、商場 80-140 分、觀景拍照 20-40 分),沒有用 30 分鐘排一座大型博物館
- [ ] (包車)每天的用車時數**沒有超過司機可用時段**
- [ ] 每天回飯店的時間**沒有超過問卷講的最晚邊界**
- [ ] 同一天沒有排兩個同類型的大館或連著兩個購物商場
- [ ] **每一餐**都確認過能滿足**全體**的飲食限制(素食者有主食不是只有配菜);全團限制不同時確認同一家店能同時滿足
- [ ] (需要無障礙)每個場地都核對過電梯或斜坡、無障礙廁所、路面、車輛能否靠近入口;查不到的標註並建議事先致電
- [ ] (偏好較少步行或體力較弱)估算過當天總步行量與連續站立時間;久站項目沒有相鄰;每天有用餐以外實際坐著的時段
- [ ] (有年長者/兒童/嬰幼兒)休息點密度、可預約時段取代排隊、尿布台與兒童餐、推車可否進入、年齡適宜都核對過
- [ ] (保密低調需求)避開了需要實名公開登記的活動與高曝光場所
- [ ] (語言支援需求)優先選了有對應語言服務的店家;需要導覽的確認過有對應語言場次
- [ ] **每一項**的價位都落在使用者說的區間內,不是只有總計對得上
- [ ] 「其他禁忌或務必避開的事項」逐項比對過整份行程,**包含備案章節**
- [ ] 限制之間互相衝突的地方,攤開給使用者選了,沒有自己挑一個

## 三、內容密度(這一節是「比旅行社行程單更詳細」的實際標準)

- [ ] 每個項目的時間**精確到分鐘**,沒有「上午/下午/傍晚」這種模糊時段
- [ ] 每日活動數量對得上使用者選的步調:緊湊 5-6 項/天、適中 4-5 項/天、悠閒 2-3 項/天。**低於標準就是要補活動,不可以用「保留彈性」當藉口**
- [ ] 主行程每個時段**只放一個定案**(你最推薦的那一個,附推薦理由),主時間軸乾淨到可以直接照著走、可以直接轉發給司機
- [ ] 備案**獨立成章**,分餐廳/景點兩組,每個備案的欄位和主行程項目一樣完整
- [ ] 每個備案都寫明**可替換哪一段、為什麼**;會吃掉大量時間的備案,寫清楚它「不能硬插進現有行程」
- [ ] 備案涵蓋三種觸發情境:天氣、臨時關閉或客滿、行程延誤或提早結束
- [ ] 備案分**三組**:餐廳、景點與休息、**交通**(替代的移動方式,不是替代的地點)
- [ ] 每個備案有**可用性前提**(需預約/實名制的標明目前狀態,例如「本次未申請」),臨時要換時知道行不行
- [ ] 每個備案有**對同行者的適用性**(備案也要做限制回核)與**在整趟行程裡的角色**
- [ ] 備案本身的不足有一併補救(例如「園內只有輕食,想吃正餐走到對面某家」)
- [ ] (某格是二擇一)**每個選項各給一句「選了之後會怎樣」**,不是只寫「二擇一」
- [ ] **先確認過目的地能不能用 Google Maps**。可用才附連結;不可用(中國大陸等)則改寫完整當地語言地址 + 樓層店號,沒有貼一整份點不開的連結
- [ ] **每一段移動都獨立佔時間軸一行**(連 5 分鐘車程也列),不是塞在項目的交通欄位裡;每一行的結束時間就是下一行的開始時間,可以直接驗算
- [ ] 移動那一行寫到**線名/上下車站名/分鐘數/票價**的顆粒度,不是「搭電車約 40 分鐘」;包車寫車程分鐘數,車流量大的路段給區間並註明原因
- [ ] 步行可達的多個點**串成一條動線**,並明講「中間不需用車」
- [ ] 展館/大型博物館/機場/大型商場這種進去還要找路的地方,給了**內部動線**(目標區域在哪一側、報到處在哪、大眾運輸出入口在哪、離場接送安排)
- [ ] 每個項目給的是**完整營業時間**(午市晚市分段要分開寫),不是只寫「當天營業」
- [ ] **訂位或入場時要特別交代的事**寫在會用到的那一格,不是只丟在附錄(例如指定樓層/場地、需要帶什麼證件)
- [ ] 需要門票的項目都寫了**票價、是否需事前預約、預約管道**;需指定時段的寫了最晚訂票時間
- [ ] 備案裡沒有「改為室內行程」「另尋餐廳」這類等於沒有備案的句子
- [ ] 每一個「未確定」的項目都寫了**具體的下一步動作**,沒有任何地方只標「待補」就斷在那裡

## 四、編輯判斷(欄位填滿之後,這一節決定它是手冊還是表格)

標準見 `references/editorial-standards.md`。

- [ ] 每個項目的**推薦理由跟這趟行程的具體條件連結**(位置動線、時段適配、與當天其他項目互補、滿足問卷的特定限制、獨特性、風險低),不是「評價很好」「很有名」這種描述而非理由的句子
- [ ] 每個主行程項目都有**四層**:是什麼 / 為什麼推薦它 / 實用資訊 / 排程判斷,不是只有實用資訊
- [ ] 每個項目的介紹有 **3 行以上具體事實**(建築來歷、創辦人背景、招牌菜名、具體評鑑、規模數字),沒有只靠「值得一遊」「風景優美」這類形容詞充數
- [ ] **每一天的開頭有一句定調**(這天是輕鬆還是趕、唯一的硬時間是什麼)
- [ ] 明顯偏緊的段落**有寫出來它緊**,並且把時間拆開算給使用者看,附上捨棄的優先順序
- [ ] 有指出**延誤時可以從哪一段吸收**
- [ ] 相鄰項目為什麼排在一起(調性互補、同棟不用重排交通、避開午後戶外時段)有說明
- [ ] 全程的硬約束**集中列成一份短清單**(幾月幾號幾點前一定要到哪裡)
- [ ] 查到營業時間與行程衝突時,**把矛盾標出來交給使用者**,沒有默默挪時間或換項目
- [ ] 資料來源互相矛盾、或資訊有時效性風險的地方都標註了
- [ ] 單項價格標了**來源與性質**(例如「人均約 RMB 290‒345(大眾點評)」),不是裸數字
- [ ] 文件最後有**資料來源與免責**:資料整理自哪裡、哪些做過更正、數字何時查的、出發前要再確認什麼
- [ ] 有依問卷的內容偏好生成 **1-2 份主題附錄**,而且附錄有寫明各項目「接回行程的實際用法」
- [ ] 附錄項目跟主行程與備案有**交叉引用**(「順道」欄位),不是幾個互不相干的孤島
- [ ] 全文是**繁體台灣用語**,沒有「出租車」「攻略」「信息」這類來源用詞;店名地名保留當地原文,同品牌多分店的有寫明分店
- [ ] 金額標明幣別(不是只寫 `¥`,那同時是日圓與人民幣的符號);時間一律 24 小時制;單位全文統一
- [ ] 對照 `editorial-standards.md` 最後一節的反面清單,逐項確認沒有中槍

- [ ] 一頁式速查總表(每天一行)
- [ ] 每日時間軸
- [ ] 航班資訊(班號、航空公司、起降時刻、航廈、艙等、飛行時間、票價、行李額度;已訂位填實際班號,未訂位列查到的候選,不留空白)
- [ ] 住宿資訊(名稱、地址含當地語言、電話、Maps 連結、入住/退房時間、規模)
- [ ] **房型表**有房型/面積/床型/房價/間數/備註;查不到的欄位寫「待補」或「請以訂房確認信為準」,沒有留空白也沒有自己填一個合理數字
- [ ] 飯店有列**到各主要行程點的車程**
- [ ] 飯店有**行程對應表**(每天幾點出發、去哪、車程幾分、幾點回飯店)
- [ ] 飯店設施不是只列出來,有寫**哪個設施適合排在哪一天、為什麼**
- [ ] 司機/接送通知摘要(含**回程返抵後**的安排),可直接轉發
- [ ] 司機摘要的地址是**司機看得懂的語言**(當地司機用當地語言全稱含門牌樓層與出入口;語言不同時雙語並列)
- [ ] 司機摘要**按日切開、每份自成一體**,不是一份要司機自己從總表挑出今天的;包車註明了當天用車起訖與時數
- [ ] (同行者當天走不同行程)時間軸**分軌呈現**,標明各軌是誰、各自的移動與車輛,分開與會合時間點明確;沒有兩軌同時要用同一台車
- [ ] 訂位狀態追蹤表(狀態/訂位編號/負責人/最晚要訂的日期),**含需要安排的人**(導遊、口譯、攝影、當地窗口)與需預約的導覽場次
- [ ] **狀態徽章標在時間軸每一格與項目介紹裡**,不是只放在追蹤表;時間軸開頭有徽章與類型的圖例
- [ ] (某格人數與同行總人數不同)**逐項人數標出來了**,沒有只寫「已預定」
- [ ] **票價對回了行程當天的類別**(平日/假日/季節)並寫出理由,不是只給一個區間
- [ ] (分時段入場)寫出了**行程時間適用哪一個場次**
- [ ] 購票管道分了**當地與境外**(當地小程序/App 非當地居民辦不了,要給境外平台)
- [ ] (會搶票的項目)寫了**開賣時間**
- [ ] (實名制)寫明**每個人都要各自辦**與需要的證件號,不是只寫「實名制」
- [ ] (有硬性限制或矛盾)用了**「務必」這個專屬欄位**,沒有混進「建議」裡被讀過去
- [ ] (攝影或景觀類項目)**最佳時段獨立列出**,不是只藏在推薦理由裡
- [ ] 票價有變動或不確定時標了出來
- [ ] 餐廳用「推薦菜色」、景點商場用「重點」——**欄位標籤依項目類型換**
- [ ] **排除的項目有明講**「本次不做什麼、為什麼、移到備案哪裡」;同一建築或品牌有多個相似場地時標了「不是那個」
- [ ] 相似容易混淆的項目之間**寫出了差別**
- [ ] 兩個項目之間的**空檔有寫出來並給了用法**,沒有留白
- [ ] (商務或接待行程)會議/拜訪/展會/接待項目用的是**商務類欄位**(對方單位與聯絡人電話、報到方式、我方出席者與接待人員時段、要帶的東西),不是拿景點的欄位硬套
- [ ] (商務或接待行程)行前清單有**商務那一組**:名片、伴手禮與收禮對象、簡報檔與線材、要列印的文件、參展證或邀請函、正式服裝、送禮時點
- [ ] (H 類問到有不宜寫入的內容)那些內容**整段隱去**而不是改成模糊寫法;需要時另做對外版並在製表資訊標明
- [ ] 費用估算摘要:分項 + **每人總計區間 + 全團總計**三層都有,幣別/匯率/匯率查詢日期齊全
- [ ] 費用是**逐項算出來的**(餐飲逐餐人均 × 人數加總,不是一個籠統的每日餐飲預算);雜支另列
- [ ] 費用裡**已訂與未訂分開標**,沒有讓使用者以為整個總額都已鎖定
- [ ] 某項估算的不確定性大到會影響總計時,**反映在區間寬度上或在總計旁註明**,不是只在那一列加註解——使用者看的是總計
- [ ] 估算與使用者給的預算**差距顯著時主動指出**;低很多要說「不必為花完預算而升級」並依對行程目標的幫助排序給升級選項,高出要說超出多少與主因
- [ ] (自駕且單一駕駛人)含酒類的項目標明了**駕駛人不能參與**並給替代做法
- [ ] 行前準備清單(證件、電壓插座、依實際天氣的衣物建議、藥品、付款方式、上網方案)
- [ ] 實用資訊附錄(簽證入境、時差、電壓、通訊、貨幣、基本當地用語)
- [ ] 實用資訊附錄含**網路與服務可用性**:哪些常用服務當地不能用與替代品、付款方式的實際限制、叫車方式、是否需要 VPN 且要出發前裝好
- [ ] (此行為參加展會)展會全名屆數、會期、場館、目標展區、是否需事前登錄或購票、參展證狀態都問到並寫進行程
- [ ] 緊急頁(報案救護、鄰近醫院、駐外館處急難救助、保險 24h、信用卡掛失、飯店當地語言地址與電話、使用者提供的緊急聯絡人)

## 六、檔案技術要求

- [ ] 單一 HTML 檔,CSS/JS 全部內嵌,**字體沒有外連**(Google Fonts 也不行,離線要能看)
- [ ] (Claude Code)是**完整 standalone 文件**:`<!doctype html>`、`<html lang>`、`<head>`、**`<meta charset="utf-8">`**、`<meta viewport>`、`<body>` 齊全。少了 charset,本地開檔中文日文會亂碼
- [ ] (Claude Code)檔案**不在 session 暫存/scratchpad 目錄**,存在使用者指定位置或專案根目錄的 `itineraries/`,且回覆裡給了絕對路徑
- [ ] (檔案在 git repo 裡)`itineraries/` **已被 `.gitignore` 排除**;行程裡有訂房編號、電話、費用,不該進版本控制
- [ ] **先取得視覺設計準則才開始做視覺**(claude.ai 讀 `/mnt/skills/public/frontend-design/SKILL.md`;Claude Code 用 `Skill` 呼叫 `artifact-design`),成品不是樣板感
- [ ] 有基本 `@media print` 樣式,列印時日期分頁籤全部展開(不是只印出當前那一頁)
- [ ] 列印樣式有**最後一個分頁區塊的 `break-after:auto` 例外**,不會多印一張白紙
- [ ] 圖例有**「圖例」這個標題**,不是一排沒有說明的色點與詞彙
- [ ] **只交付了詳細版一份**,沒有同時做衍生版(B5 列印手冊與 A4 精簡版都是內容定案後的另一個階段)
- [ ] 離線可讀:地址、電話、營業時間都以文字寫在頁面上,沒有任何必要資訊只靠連結交代
- [ ] 手機寬度可讀
- [ ] **交付時把檔名與完整路徑講出來,並問了要不要改**;若使用者改名,圖庫資料夾(與相對路徑的 `<img src>`)一起改
- [ ] 檔名含目的地 + 日期 + 版本;依環境交付(claude.ai:存 `/mnt/user-data/outputs/` + `present_files`。Claude Code:交付本地檔案的絕對路徑)
- [ ] (Claude Code)**問過使用者要不要另外發布成 artifact**,而且只有在他同意之後才發布。沒問就發、或他沒回答就發,都是錯的
- [ ] **交付回覆講了前六件事**:哪些是預設值或估算、訂位表最近的截止日、還需要使用者提供什麼、查證發現的矛盾與風險、清單裡決定不補的項目與理由、配色的由來
- [ ] **配色取自這趟行程的主題**,不是每次同一組;設定檔若記了視覺偏好則以設定檔為準
- [ ] 交付訊息**用一句話說明配色的由來**,讓使用者知道這是選出來的、也可以換(不要另外問他要什麼風格);使用者說出偏好時存進設定檔
- [ ] (使用者在交付當下就勾了衍生版)**沒有直接開工**,先回了一則確認把他該先看的東西指出來(預設值、還缺什麼、矛盾與風險),並說明現在改比較省;他確認後才開始,沒有追問第二次
- [ ] **主動問了接下來的四個選項**(加使用者自己的圖片 / 發布成 artifact / 做 B5 列印手冊 / 做 A4 精簡版),沒有等使用者自己想到。兩種衍生版**各自是一個選項**,沒有併成「要不要做衍生版」。後兩項尤其要講——使用者不會知道有這些選項
- [ ] (使用者要加圖片時)每一張圖都**用 `Read` 實際打開看過**,不是憑檔名判斷;每張給了一個推薦位置 + 一到兩個備選讓使用者選
- [ ] (已插入圖片)`alt` 寫實際內容而非檔名、`figcaption` 寫這張圖在行程裡的意義、有 `loading="lazy"`、`width`/`height` 實際像素與 `img{max-width:100%}`;版本號 +1
- [ ] **圖庫資料夾名稱 = HTML 檔名去掉版號**;檔名帶版號、資料夾不帶,兩者一眼看得出是一組;詳細版與各衍生版共用同一份圖庫
- [ ] (有自由授權圖片)放在 `pics/cc/`,並有 `_licences.json` 記錄檔名/授權/授權網址/作者/原始頁面;圖說標了作者與授權
- [ ] (已插入圖片且用相對路徑)告訴使用者**搬移手冊要連同圖庫資料夾一起搬**,以及**發布成 artifact 時相對路徑會讀不到**

## 七、B5 列印手冊(只有做這一份衍生版時才跑這一節)

- [ ] 用**固定尺寸頁面容器**(`.page` 有固定 `width`/`height` 與 `overflow:hidden`),不是靠 `break-after` 讓內容自己斷
- [ ] `@page` 的 `margin:0`,頁邊留白由 `.page` 的 `padding` 負責,兩邊沒有疊加
- [ ] 有 `.page:last-child{page-break-after:auto}`,最後不會多印一張空白頁
- [ ] 紙張尺寸明確,B5 有確認過是 **ISO(176×250mm)還是 JIS(182×257mm)**
- [ ] 每頁有 **running footer**:章節名 + 頁碼;頁碼與實際頁序一致
- [ ] 螢幕上有**列印指引與按鈕**,而且指引寫了「**實際大小 100%**」與「**勾選背景圖形**」——不勾背景,所有色塊會消失
- [ ] 指引寫了**總頁數與紙張尺寸**
- [ ] **附了溢出自檢腳本**(以頁腳 `offsetTop` 為上限、留 8mm 邊界、回報超出的 mm 數),結果顯示在工具列
- [ ] **FITCHECK 是綠色的** —— 有任何一頁溢出就回去改內容,不交付
- [ ] **實際打開看過幾頁**,優先看含框、含表格、含圖的頁 —— FITCHECK 量高度,量不出文字被拆散、分隔符掉在行尾這類排壞
- [ ] 元件樣式**沒有選裸標籤**(`.must b`、`.tip i`、`.card em` 這種);標題用自己的 class,`<b>`/`<em>` 留給內容做行內強調
- [ ] 列印指引寫了**紙張尺寸的實際 mm 數與總頁數**,並附裝訂建議(雙面、短邊翻頁)
- [ ] 紙本上使用者還沒提供的欄位(保險專線、掛失電話、緊急聯絡人)**給了可以手寫的底線**,不是照搬螢幕版的括號註記
- [ ] 編排順序:封面 → 製表資訊與版本 → 速查總表 → 航班住宿 → 各日(日扉頁 + 一項一頁)→ 備案 → 附錄 → **緊急頁** → 資料來源與免責
- [ ] **日扉頁有「今日重點」框**,寫的是「你今天要注意什麼」(關鍵決策、太滿怎麼調、訂不到位怎麼辦),不是重複時間軸
- [ ] 單項頁照**固定骨架**:類型標籤 → 名稱 → 副標 → 圖與圖說 → 背景/亮點 → 重點(小標+說明) → 實用資訊行 → 狀態徽章 → 建議
- [ ] 圖片用 **base64 內嵌**(列印版常要存成 PDF 再寄出,相對路徑會破圖)
- [ ] **每張圖的版位是按「實際長寬比 + 主體分布」兩件事選的**,不是全部塞進同一個寬扁框
- [ ] 橫向帶狀主體(道路、小徑、稜線、花田)用了寬扁版位;**縱向延伸主體(瀑布、塔、人像)沒有被塞進寬扁版位**
- [ ] 步驟 3 打開看圖時得到的主體分布資訊,**真的用在選版位上**,不是只用來寫圖說
- [ ] **直幅與正方的圖用圖文並排版位**,沒有被 `object-fit:cover` 裁成一條橫帶
- [ ] **每一張都判斷過裁切重心**,主體不居中的用 `object-position` 指定;構圖不能裁的改 `contain` 或並排。沒有靠「不設定剛好也對」
- [ ] 日扉頁的時間軸用**兩欄表格**(時刻 | 內容),不是 flex;每列用類型 class 上色
- [ ] **每個日扉頁都有圖例**(四種列類型 + 徽章的意思),不是只有第一天有
- [ ] 字級用 **pt**,內文 9.5–10pt;標題襯線 + 內文無襯線;字體不外連
- [ ] 色彩用語意化 token 且**項目類型有分色**(景點色/餐飲色),翻頁能一眼認出這頁是吃的還是看的
- [ ] 大章節用**群組標題放在該組第一頁頁首**,沒有浪費紙的獨立分隔頁
- [ ] 單項頁做成**可重複的元件**(card/irow/sched 等固定 class),不是每頁手刻樣式
- [ ] 狀態有**顏色編碼**(紅=不能違反、綠=已完成、類型色分景點餐飲),而且**每個顏色都有文字標籤**——印成黑白或色弱讀者只看顏色會全部失效
- [ ] 詳細版仍然保留,沒有被列印版取代
- [ ] 要不要帶圖是**為這一份單獨問過的**,不是沿用詳細版或 A4 精簡版的答案
- [ ] 交付訊息講了**生成自詳細版哪一版**、總頁數與 FITCHECK 結果、以及**之後改內容要回詳細版改再重生成**
- [ ] (A4 精簡版還沒做過)交付訊息**用一句話提了一次**,沒有再開一輪提問,也沒有在他沒回應時追問

## 八、A4 精簡版(只有做這一份衍生版時才跑這一節)

- [ ] 是**從定案的詳細版生成的**,不是另外寫一份;內容沒有任何一項是詳細版裡沒有的(精簡版不做新的查證)
- [ ] 砍掉的區塊照規則走,不是憑感覺挑:**司機摘要、訂位狀態追蹤表、行前準備清單、實用資訊附錄**都砍了
- [ ] 時間軸**格內欄位**砍掉了地址、地圖連結、完整營業時間、狀態徽章、購票管道、實名制細節、票價類別判定;骨架(時間 + 項目 + 移動行 + 該日定調)留著
- [ ] **一頁式速查總表與全程硬約束清單留著** —— 這是決策者最常看的一頁,砍了整份就沒有意義
- [ ] **緊急資訊壓成一行留著**(當地緊急電話 + 飯店 + 我方窗口),沒有為了精簡整段拿掉
- [ ] **各項目的介紹一字未減**,沒有被壓縮成一句話 —— 敘事是精簡版存在的理由
- [ ] **費用要不要顯示問過使用者**(或依問卷 H 類已有的答案處理),不是自己決定的
- [ ] A4 直式、內容自然流動,**沒有套用 B5 的固定頁面容器技法**,也沒有一項一頁
- [ ] 頁尾標的是**本頁涵蓋的項目名 + 頁碼**,不是只有章節名
- [ ] 頁首標了**地理區域 + 日期**
- [ ] 螢幕上有列印指引,寫了「實際大小 100%」與「勾選背景圖形」
- [ ] 檔名是 `-brief-vN.html`,與詳細版共用同一個不帶版號的資料夾
- [ ] 製表資訊標明**這是精簡版**,而且寫了**生成自詳細版哪一版**(例如「brief-v2 · 生成自 v3」)
- [ ] 要不要帶圖是**為這一份單獨問過的**,不是沿用詳細版或 B5 的答案;有放圖的話是 base64 內嵌
- [ ] 交付訊息講了**生成自詳細版哪一版**、費用有沒有顯示、有沒有放圖、以及**之後改內容要回詳細版改再重生成**
- [ ] (B5 列印手冊還沒做過)交付訊息**用一句話提了一次**,沒有再開一輪提問,也沒有在他沒回應時追問
- [ ] 詳細版仍然保留,沒有被精簡版取代

## 九、隱私

- [ ] 存檔內容只有差旅規劃偏好,沒有健康/身心障礙/種族/宗教/政治立場等敏感類別
- [ ] (Claude Code)設定檔存在**專案根目錄的 `profiles/`**,不是 Claude Code 的記憶目錄;`profiles/` 已被 `.gitignore` 排除;而且**回覆裡告訴了使用者檔案路徑**
- [ ] 使用者提供的醫療相關資訊,在存檔與行程文件裡都已轉化為中性的規劃描述(例如「步調寬鬆、備妥休息時間」),沒有寫成診斷或病名

視覺質感不能取代內容密度。頁面做得漂亮但每天只有三行、餐廳只寫「當地料理」、交通只寫「搭車前往」——那是一份美觀的空殼,不是這個 skill 要交出去的東西。
