# 問卷題庫

分成 A–H 八大類(另有 A-2 依事由的分支題組)。設計時請對照問卷工具的限制:單次最多 3 題(claude.ai)或 4 題(Claude Code),每題最多 4 個選項(工具名稱見 SKILL.md 的環境對應表)。可依對話情境合併或跳過不相關題目,這裡的分類與選項是起點,不是必須逐字照問的腳本。

若某題答案超過 4 個常見選項(例如目的地城市、國家),不要硬塞進 options,改用一般文字提問,或列出最常見的 3 個 + 「其他(請說明)」。

**每一項都標了優先級,照著標記走,不要每題都問:**
- **【必問】** —— 不問就會排錯、或根本排不出來。一定要拿到明確回答,不能用推測補上。
- **【條件】** —— 只在括號寫的條件成立時才問。條件不成立就直接跳過,不要為了問卷完整而硬問無關的題目(問卷輪次太多會讓使用者放棄)。

> **通用原則,適用 B–H 全部類別**:只要同行者不只一人、且身分/角色不同(老闆、老闆的配偶、特助、客戶等),**任何「偏好類」問題都不能預設整團答案一致**——不只是 B 類的體力/飲食,艙等(C)、房型與住宿等級(D)、步調與用餐時間偏好(E)、緊急聯絡人(G)全部都可能因人而異。問完人數與組成後,針對後續每一類偏好,先確認「這幾位同行者在這件事上的需求是否相同」,相同才套用同一組答案;不同就分別記錄,並在最終確認清單與行程文件裡清楚標示是哪一位的安排,不要籠統寫成單一人稱(例如「老闆的行程」)卻其實混雜了不同人的需求。

---

## 0. 三個地基項目

以下三件事是整份行程的地基,漏掉任何一項,後面排出來的東西全部要重排。問卷第一輪就要把它們確立:

1. **目的地**(見 A)
2. **總天數 / 出發與回程日期**(見 A)
3. **固定錨點 —— 已確定、時間不能移動的項目**(見 A)

第 3 項最容易被忽略,但它決定了整份行程的骨架:錨點先落位,其他活動繞著錨點排。沒有先問錨點就開始排程,等於在還不知道哪幾格已經被佔用的情況下填表。

## A. 基本行程資訊

> **這一類全部都要在問卷中明確問到、明確拿到使用者的回答,不可以從對話裡先前提過的範例、假設情境、或使用者隨口帶到的字詞去推定。** 即使先前對話中(例如使用者說「先跑個範例看看」時舉的例子)提過某個目的地,只要使用者本人沒有在這次的問卷流程裡親口確認,就必須當作未知,重新詢問。目的地問錯,後面排的整趟行程都是廢的,這是最不能省略的一步。

- 【必問】目的地(國家/城市):開放式提問,不要用選項卡片預設答案,務必等使用者明確回覆
- 【必問】國內 / 國外
- 【必問】出發與回程日期(或總天數)
- 【必問】本次行程事由:商務出差 / 純旅遊 / 接待貴賓 / 獎勵旅遊 / 其他
  - **拿到答案後,必須接著問 A-2 對應的那一組分支題目,不可以拿著這個標籤直接去排行程。**
- 【必問】出發地(城市/機場)
- 【必問】**這趟是單一城市還是多城市**。多城市的話要問到:各城市的順序、每個城市各停留幾晚、城際交通方式偏好(高鐵/鐵路 / 內陸或跨國航班 / 包車 / 交給你建議)。多城市行程的移動日會吃掉大量時間,不先問清楚會排出一份每天都在趕車的行程
- 【條件】(國外行程)全體同行者持用的護照國籍——**國籍決定簽證與入境規定**,不可預設是本地護照;團內國籍不同時要逐位確認
- 【必問】**固定錨點:這趟行程裡有沒有已經確定、時間不能移動的項目?**
  - 用開放式文字問,不要用選項卡片。舉例讓使用者好回答:已排定的會議、已買的門票/演唱會/球賽/展覽、已訂位的餐廳、已訂好的飯店或包車、家族聚會、必須趕上的返程班機或轉乘。
  - 請使用者針對每一項給出:**日期 + 時間 + 地點 + 是否還有調整空間**。
  - 使用者回答「沒有」也要明確拿到這個「沒有」。**不能因為對話裡沒人提到就自行當作沒有錨點。**
  - 排程時錨點優先落位,其他活動繞著錨點排。不可以為了行程看起來漂亮而挪動或忽略錨點;若錨點之間的時間物理上排不開,要回報衝突請使用者裁決,不要自己硬塞。

## A-2. 依事由的分支追問(不可跳過)

事由只是一個標籤,真正決定行程骨架的是底下這些細節。**選了哪個事由,就必須問完對應的那一組。** 拿著「商務出差」四個字去排一份純觀光行程,是這個 skill 最容易犯、後果也最嚴重的錯誤。

### 事由 = 商務出差
- 【必問】會議/工作行程的確切時間與地點:哪一天幾點、在哪裡、預計多久。這是最高優先的固定錨點,整趟行程繞著它排
- 【必問】拜訪對象:公司/單位、部門、聯絡人姓名與聯絡方式
- 【條件】(需拜訪外部單位)是否需要準備伴手禮、名片、簡報設備或列印文件
- 【條件】(當地語言不通且為正式商務場合)是否需要安排商務口譯
- 【條件】(工作日有空檔時段)空檔希望怎麼安排:回飯店休息 / 商務中心或飯店辦公 / 安排參觀或用餐 / 保留彈性不排
- 【條件】(需要請款)是否需要保留發票/收據,以及請款需要的憑證形式
- 【條件】(此行是為了參加展會、會展、論壇、發表會)展會的專屬資訊:**展會全名與屆數、會期起訖、場館、目標展區或館別、是否需要事前線上登錄或購票、是否已有參展證或邀請函、同期是否有其他展要一起看**。展會是這類行程的核心錨點,而且大型會展的動線、排隊進館、館間移動會吃掉大量時間,只寫「去看展」排不出可執行的行程

### 事由 = 接待貴賓
- 【必問】貴賓的抵達與離開班機、日期時間、航廈——這決定接機/送機時刻表,沒有它接送安排全是空的
- 【必問】我方接待人員名單,以及各自負責哪些時段
- 【必問】對外聯絡窗口(姓名 + 電話)——司機/接待通知摘要一定要有這個欄位
- 【必問】宴請規格:是否需要包廂、正式宴席、席次安排、實際人數(含我方陪同)
- 【條件】(公司慣例或對方層級高)是否需要安排送禮、致詞、合影、公司參訪或廠區導覽

### 事由 = 純旅遊 / 獎勵旅遊
- 【必問】這趟最想達成的一兩件事:特定想去的地點、特定想吃的餐廳、紀念性質的安排(生日、結婚週年等)。這比「喜歡自然還是古蹟」這種分類題更能決定行程好不好
- 【條件】(獎勵旅遊)是否有全體集合活動、頒獎晚宴、統一行動的時段要求,以及自由活動時段的長度
- 【條件】(有隨行家屬且需求不同)是否需要分組行動:部分人參加活動、部分人走另一套行程

### 事由 = 其他
- 【必問】請使用者具體說明事由,並追問「這趟裡有哪幾件事是一定要完成的」,把答案當成錨點處理

## B. 對象資料

> 人數與組成問完後,先確認「這幾位同行者的體力/步行偏好、飲食限制是否一致」(見上方通用原則)。

- 【必問】人數與組成:單人 / 2-4 人小團 / 5 人以上團體,並請使用者說明每位同行者的身分角色(例如「老闆+老闆娘+特助」)
- 【必問】身分定位:公司高階主管 / 一般員工 / 客戶或貴賓 / 家庭旅遊
- 【必問】是否常走動、體力狀況:習慣長時間步行 / 偏好較少步行 / 需要無障礙安排
- 【條件】(上題回答「需要無障礙安排」)具體需要哪些:輪椅可通行的動線 / 電梯與無障礙廁所優先 / 避開階梯與碎石路面 / 需要協助租借輪椅或代步車
- 【條件】(組成含未成年或年長者)隨行成員的年齡層與對應需求:
  - 嬰幼兒 —— 嬰兒床、推車可行性、尿布台、兒童餐具
  - 學齡前/學齡兒童 —— 車輛兒童座椅、兒童餐、適齡活動、午休時段
  - 年長者 —— 步調、休息點密度、座位需求、避免久站排隊
- 【必問】飲食限制或偏好(逐位確認,不要假設全團一致):無特殊限制 / 素食 / 特定禁忌(請說明) / 需要正式宴請規格
- 【條件】(國外且當地非中英文通用)語言支援需求:成員可自行溝通 / 希望優先選有中文或英文服務的店家與飯店 / 需要隨行導遊或翻譯

## C. 交通
- 【必問】航班艙等偏好(留意是否全員同艙等,見上方通用原則):經濟艙 / 豪華經濟艙 / 商務艙 / 頭等艙
- 【必問】航班偏好:直飛優先 / 可接受轉機 / 時段有特定要求(請說明)
- 【必問】機場接送:需要司機接送 / 自行前往 / 尚未決定
- 【條件】(需要司機)是否要提前通知固定座車(需要,請提供聯絡窗口 / 需要,尚未有固定司機 / 不需要)
- 【必問】機票目前的狀態:已訂位(請提供班號與時刻,行程要填實際班號) / 未訂位(行程要列查到的候選航班) / 已委由旅行社或秘書處理
- 【條件】(未訂位且希望協助查候選或代訂)護照上的英文姓名拼音、**護照效期是否距回程日 6 個月以上**(效期不足會直接無法出境,是實務上最常出事的一項)、常客會員卡號與選位偏好
- 【必問】市內交通方式:全程包車 / 大眾運輸為主 / 步行+少量計程車 / 混合安排由你建議
- 【條件】(全程包車或有固定座車)**包車是幾小時制、司機的可用時段到幾點、超時如何計費**。這是排程的硬約束:10 小時制的包車配上 08:30 出門、21:20 回飯店的行程就是超時,排之前不知道,排出來的行程根本無法執行。也要問清楚司機的用餐與休息時間怎麼安排
- 【條件】(需要車輛)車型與座位需求:實際乘車人數 + 行李件數決定要幾人座或幾台車;是否需要兒童座椅、輪椅可上下的車型、後車廂容量(高爾夫球具、大型行李)
- 【必問】回程返抵後的安排:需要接送回家或公司 / 自行返回 / 尚未決定(接送只問去程、漏掉回程是常見缺口)
- 【條件】(國外或有特殊裝備)行李與裝備需求:托運件數、是否攜帶高爾夫球具/滑雪裝備/樂器/醫療器材(影響車輛選擇與航班行李額度)

## D. 住宿
- 【必問】星級/等級:五星級或同等 / 精品/設計旅店 / 商務型 / 依預算彈性 / **舉一家飯店當基準**(見下方「用實例回答等級題」)
- 【必問】飯店目前的狀態:已訂(請提供飯店名稱與訂房編號) / 未訂,需要建議 / 已委由他人處理
- 【必問】房型與間數需求:單人房/套房/是否需分房,並確認是否所有同行者住同一飯店同等級,或有人需要分開安排(見上方通用原則)
- 【條件】(觸發條件見下方「飯店是目的地還是基地」)**飯店在這趟行程裡的角色**:飯店本身就是目的地(大部分時間在館內:溫泉、滑雪、SPA、館內餐飲)/ 各半(白天出去、傍晚回來用設施)/ **飯店是基地**(睡覺與早餐,行程以周邊為主)。**沒有觸發時預設是「飯店是基地」**,不用問
- 【條件】(角色答「各半」或「飯店是基地」)位置偏好:市中心 / 鄰近主要行程地點 / 鄰近機場方便進出 / 交給你安排。**答「飯店就是目的地」時不要問這一題** —— 那種情況下選飯店看的是設施不是位置,問位置只會誤導

### 用實例回答等級題

**等級、價位、品味這類問題,讓使用者舉一個實例比勾一個抽象等級精確得多。** 「五星級」涵蓋的範圍太寬 —— 商務五星、度假村五星、設計酒店五星是完全不同的東西;而「像我上次住的 XX」一句話就把等級、風格、房型偏好、甚至服務期待全講完了。

適用於**住宿等級**與**餐飲價位**兩題,選項裡要留這條路,不要只給抽象分級。

使用者舉了實例時要做三件事:

1. **去查那一家**,把它的等級、價位帶、風格、代表性設施查出來 —— 不要憑名字猜
2. **把推導出的標準寫進最終確認清單**(「以 XX 為基準:每晚約 TWD 15,000–18,000、當代設計、房內有陽台、館內有 SPA」),讓使用者確認你理解對了。**這一步不能省** —— 你對那家飯店的理解可能跟他心裡的重點不一樣(他要的可能只是「安靜」)
3. **確認那家是不是就是要訂的那家。** 使用者舉的實例如果剛好在目的地,要問清楚是「以它為基準找同級的」還是「就訂它」。這兩種完全不同,不問就會白排

實例存進設定檔時記成基準而不是硬性指定(見下方設定檔儲存格式)。

### 飯店是目的地還是基地

**現行流程預設飯店是基地** —— 睡覺、早餐、放行李,行程以周邊景點為主。這對大部分行程是對的,但對某些飯店完全錯:館內就有滑雪場與纜車、帝王蟹自助、溫泉大浴場、私人湯屋、獨棟別墅型住宿(NOT A HOTEL 那類),或飯店本身就是這趟要去體驗的東西。這種情況把人拉出去看周邊景點,是把行程排壞了。

**這一題要在選飯店之前問**,因為它決定的不只是排程,還有**選飯店的標準本身** —— 飯店是目的地時看設施,飯店是基地時看位置。

**條件觸發**(不必每趟都問,問了會變成噪音):

- 住宿等級選了「五星級或同等」或用實例舉了一家高端飯店
- 已訂或指名的飯店本身是溫泉旅館、滑雪度假村、離島/山區度假村、別墅型住宿
- 目的地本身以住宿體驗聞名(北海道雪季、沖繩/石垣島、瀨戶內、馬爾地夫這類)

答「飯店就是目的地」或「各半」時,**排程與輸出都要跟著換**,見排程方法檔的「飯店為主的日子」一節與 HTML 規格的住宿區塊。

## E. 行程規劃類型
- 【必問】整體步調(留意是否全員一致,見上方通用原則):緊湊(盡量排滿) / 適中 / 悠閒(保留大量彈性時間)
- 【必問】室內外活動比例:偏好室內為主 / 室內外均衡 / 偏好戶外為主 / 交給你依天氣建議
- 【條件】(行程含戶外活動)戶外活動接受度:可接受高溫/日曬 / 需要遮蔭或室內備案 / 雨天需完整備案
- 【必問】每日作息:早出晚歸 / 晚起悠閒 / 依當天行程彈性調整
- 【必問】**每日的時間邊界要具體,不能只有上面那個分類**:最早幾點可以出門、最晚幾點要回到飯店。「早出晚歸」在排程時無法換算成時刻,08:30 出發跟 10:30 出發差一整個上午
- 【必問】**用餐時間偏好**:午餐與晚餐習慣幾點吃(例如午餐 12:00-12:30、晚餐偏早 17:30 或偏晚 19:30)。用餐時段是整天排程的骨架,不是細節——先定用餐時間,景點才有地方放
- 【條件】(步調偏悠閒或有年長者同行)是否需要每天安排回飯店休息的時段,以及大約需要多久
- 【必問】內容偏好(可複選,留意每位同行者想要的類型是否不同):自然景觀、文化古蹟、美食、購物、休閒放鬆、商務會談安排

## F. 預算
- 【必問】每人每日預算區間,或總預算(開放式提問,或給 3 個級距讓使用者選 + 其他)
- 【必問】報價與估算要用哪個幣別呈現(例如新台幣 / 當地貨幣 / 兩者並列)
- 【必問】價位接受度:高端不設限 / 中高階 / 大眾價位 / 依項目彈性(例如住宿高端但餐飲彈性)/ **舉一家餐廳當基準**(見 D 類的「用實例回答等級題」)

## G. 特殊需求
- 【必問】保密 / 低調需求:需要低調安排(避免曝光行程) / 一般安排即可
- 【必問】緊急聯絡人(若同行者不只一人,確認是否每人各自提供,見上方通用原則) / 隨行醫療需求(若使用者主動提供醫療相關資訊,規劃時轉化為「步調寬鬆、備妥休息時間」等中性安排描述,不要在存檔或行程文件中記錄診斷或病名)
- 【必問】保險安排:需要協助確認 / 已自行處理
- 【必問】(國外或兩岸行程)**目的地專屬證件的辦理狀態與效期**:台胞證、港澳通行證、ESTA、ETA、電子簽等,每個目的地要求不同。護照有效不等於能入境,而且這類證件常常在行程中途也要用到(核驗身份、實名制入園),不是只在通關時用一次
- 【條件】(國外行程)當地上網怎麼處理:已有漫遊方案 / 需要建議 SIM 或 eSIM / 需要 Wi-Fi 分享器 / 交給你建議
- 【條件】(國外行程)是否需要協助確認簽證與入境規定(電子簽/ETA、入境表單、疫苗或健康聲明)
- 【必問】其他禁忌或務必避開的事項(自由文字)

## H. 產出與交付

- 【必問】**這份行程要給誰看**:只有自己 / 需要轉發給司機 / 需要交給秘書或助理執行訂位 / 需要給同行者每人一份 / 需要對外(客戶、貴賓)。交付對象決定文件怎麼寫——要轉發給司機的話,接送摘要必須能單獨複製出來;要交給秘書執行訂位的話,訂位追蹤表要標明負責人與截止日
- 【條件】(需要交給他人執行)是否要在文件裡標註各項的負責人
- 【條件】(對外使用)是否有不宜寫入文件的內容(價格、內部人事、行程目的)

## 建議分輪範例

題庫項目很多,但**不要每題都用卡片問** —— 那會變成十輪以上的問答。分輪的原則:

- **需要在選項之間權衡的**(艙等、步調、住宿等級、室內外比例)→ 用問卷工具的卡片,一輪最多 3-4 題(依環境)
- **答案本來就是具體事實或數字的**(目的地、日期、包車時數、用餐時間、幾點出門、聯絡窗口)→ **好幾題合併在同一則訊息裡用文字問**,不受 3 題限制
- **【條件】題只在條件成立時才佔位置**,不成立直接跳過

照這個原則,一般情況可以壓在 5-6 輪:

(告知使用者時要說「**大約** 5-6 輪,視你的答案可能多一兩輪追問」——【條件】題成立時會追加,講死了跑成 8 輪會讓使用者覺得被騙。)

| 輪次 | 形式 | 內容 |
|---|---|---|
| 1 | 文字合併 | 目的地、日期或天數、出發地、是否多城市(多城市再問順序與各城晚數) |
| 2 | 卡片 3 題 | 事由、國內/國外、人數與組成 |
| 3 | 文字合併 | **固定錨點**(開放式,要具體到日期時間地點)+ A-2 依事由的分支題組(會議時間地點/貴賓班機與接待窗口/最想達成的事) |
| 4 | 卡片 3 題 | 體力狀況、艙等、住宿等級 |
| 5 | 卡片 3 題 | 步調、室內外比例、價位接受度 |
| 6 | 文字合併 | 每日時間邊界與用餐時間、包車時數與司機可用時段、飲食限制、內容偏好、交付對象、證件狀態、其他禁忌 |

再加上【條件】題成立時的追問(無障礙細節、年齡層需求、語言支援、機票與訂房狀態、車型、漫遊、簽證協助),視情況插在對應輪次後面。

**兩個掛在第 4 輪後面的追問,不佔新輪次:**

- **住宿等級答了「舉一家飯店當基準」** → 追問是哪一家,並確認「以它為基準」還是「就訂它」。這是同一則回覆裡的一句追問
- **住宿等級是五星級或同等 / 舉的實例是高端飯店 / 目的地以住宿體驗聞名** → 問**飯店在這趟的角色**(目的地 / 各半 / 基地)。**Claude Code 一輪最多 4 題**,可以直接併進第 5 輪的卡片;**claude.ai 一輪只有 3 題**,第 5 輪已經滿了,要跟其他條件追問合成一輪,不要為了它單獨開一輪

兩題都是條件題,一般行程不會觸發,不會讓所有人的問卷都變長。

**同行者身分不同時**,偏好類的每一輪都要先確認「這幾位在這件事上需求是否相同」(見上方通用原則),不要問完一個人就套用到全團。

## 設定檔的儲存格式

存放位置:claude.ai 是 `/people/<名稱>.md`;Claude Code 是**專案根目錄下的 `profiles/<名稱>.md`**(要被 `.gitignore` 排除)。


用固定結構寫,不要每次自由發揮 —— 下次 Step 1 要逐項摘要給使用者確認,結構不一致就沒辦法逐項對照:

```markdown
---
aliases: [老闆, 董事長, Mr. Lin]
---

# 差旅規劃偏好

## 交通
- 艙等:商務艙,直飛優先
- 機場接送:需要固定座車;聯絡窗口 <姓名/電話>
- 市內:全程包車,習慣 10 小時制

## 住宿
- 五星級或同等,偏好鄰近主要行程地點
- 房型:單人房
- 等級基準:以東京安縵為準(當代設計、安靜、房內浴缸有景;不是要訂它)
- 飯店角色:通常是基地;北海道雪季那趟例外,當時選的是「各半」

## 步調與內容
- 步調適中,室內外均衡,偏好較少步行但行程要實在
- 內容偏好:自然景觀、文化古蹟、美食
- 每日邊界:最早 09:00 出門,最晚 21:00 回飯店
- 用餐時間:午餐 12:30、晚餐 18:30

## 預算
- 住宿高端不設限,餐飲彈性

## 產出與交付
- 需要可轉發給司機的接送摘要;訂位由特助執行
- 視覺風格:(只在使用者主動表示過偏好時才寫這一行,例如「深藍 + 銀灰、低彩度、無襯線」。沒寫就表示每趟依主題配色)

## 同行者
### 老闆娘(常同行)
- 步調偏悠閒,需要每天安排回飯店休息約 1 小時
### 特助(常同行)
- 經濟艙即可;單人房
```

**多人團體的存法**:主要對象一個檔案,固定同行、但偏好與主要對象不同的人,記在主檔的「同行者」一節底下。若其中某人也常常單獨出差,就另外開一個屬於他自己的檔案,並在兩邊用 `[[ ]]` 互相連結,不要在兩處重複記錄同一組偏好(會出現兩邊不一致)。
