# HTML 行程手冊規格

最終產出是**一份完整的 HTML 旅遊手冊**,不是聊天室裡的條列文字,也不只是一張行程表。

製作順序:
1. 先用 `view` 讀 `/mnt/skills/public/frontend-design/SKILL.md`,取得視覺設計準則(這一步不能跳過,跳過就會做出樣板感的東西)。
2. 用 `create_file` 產出**單一 HTML 檔案**,CSS 與 JS 全部內嵌在同一檔案。
3. 存到 `/mnt/user-data/outputs/`。
4. 對照 `references/output-checklist.md` 逐項檢查。
5. 呼叫 `present_files` 交付。

## 必含區塊

### 1. 製表資訊
製表日期與版本標記(例如 `v2 · 2026-08-23 製`)。行程會改版,沒有版本標記使用者會分不清手上哪份才是最新。

### 2. 行程總覽
目的地、日期、天數、對象(含每位同行者的身分角色)、事由。

### 3. 一頁式速查總表
每天一行,濃縮該日重點:住宿地、主要行程、當日固定錨點。讓人不用翻完全部細節就能掌握整趟輪廓,也方便單獨列印或轉發。

### 4. 每日時間軸
每個項目要標明:
- **精確到分鐘的當地時間**(跨時區標明是哪一地的時間;跨日抵達標 `+1`)
- 地點名稱與地址
- **Google Maps 連結**
- 室內 / 戶外標籤
- **該地點當天的營業時段**(查不到要標註「未能確認」並附已確認營業的備選)
- 交通方式:線名、上下車站名、預估分鐘數、票價(查得到就連出口編號一起寫)
- 門票價格、是否需事前預約、預約管道與最晚訂票時間
- **固定錨點要明確標示為不可調整**,不能跟其他建議活動混在一起看起來都能換

**主行程每個時段只放一個定案**——你最推薦的那一個,附上為什麼推薦它。主時間軸要乾淨到可以直接照著執行、可以直接轉發給司機,不要在同一格塞 2-3 個並列選項讓人自己選。替代方案全部集中到獨立的備案章節(見區塊 9)。

每個項目都必須是 `places_search` 或 `web_search` 查得到的真實店家,不能是隨口舉例。查不到訂位資訊時,要註明具體的下一步(例如「建議由飯店禮賓部協助訂位」),不能停在「建議」兩個字。


### 5. 航班資訊
去程/回程班號、起降時刻(標當地時間)、航廈、艙等、飛行時間。
已訂位就填實際班號;未訂位要列出查到的候選航班,**不要留空白**。

### 6. 住宿資訊
飯店名稱、地址(含當地語言寫法)、電話、Google Maps 連結、入住與退房時間、房型與間數。

### 7. 司機 / 接送通知摘要(若適用)
設計成**可以直接複製轉發給司機**的形式:幾點在哪裡接、送到哪裡、車上有幾位、聯絡窗口姓名電話。
去程與**回程返抵後**的安排都要有。未確定時要註明下一步動作,不能只寫「待補」。

### 8. 訂位狀態追蹤表
把所有需要訂的項目(機票、飯店、餐廳、門票、包車)列成一張表,每列標明:
| 項目 | 狀態 | 訂位編號 | 負責人 | 最晚要訂的日期 |

狀態用「已訂 / 待訂 / 已委外」。這是實務上使用者最常拿來用的一塊,不要省略。

### 9. 備案(獨立成章,不是主行程的附註)

備案是一個**獨立章節**,不是塞在每日時間軸裡的括號。分成「餐廳備案」與「景點備案」兩組,每組依性質排序,篇幅可以佔到整份文件的三分之一——這不是湊字數,備案寫得夠好,行程才有應變能力。

每個備案要有的欄位,和主行程的項目**一樣完整**(介紹、地址、營業時間、人均或票價、車程、Maps 連結),另外必須多一項:

- **可替換哪一段** —— 明確寫出這個備案是用來取代哪一個時段或哪一個項目,以及為什麼。例如:
  - 「適合 9/6 午餐的同棟替代」(同一棟樓 3F/4F,換了不用重排交通)
  - 「9/5 恆隆 66 下午行程的延伸晚餐」(位置直接接得上)
  - 「需要 2-3 小時的套餐制餐廳,適合取代 9/6 或 9/7 的一整段,**而不是硬插進現有行程**」

最後一種寫法特別重要:**要寫清楚這個備案不能怎麼用**。只說「可以去這家」而不說它會吃掉多少時間,使用者換上去就會把當天後面全部擠爆。

備案要涵蓋三種觸發情境:
1. **天氣** —— 雨天、高溫、颱風的室內替代
2. **臨時關閉/客滿** —— 訂不到位、休館、展期變動時的同級替代(優先找同棟或鄰近的,交通不用重排)
3. **行程延誤或提早結束** —— 例如展會提早結束時最順路的休息選項

備案裡不可以出現「改為室內行程」「另尋餐廳」這類等於沒有備案的句子。

### 10. 費用估算摘要
機票 / 住宿 / 餐飲 / 交通 / 門票分項概估區間。
即使預算是「高端不設限」也要給,讓使用者知道數量級。
必須標明**幣別、換算匯率、匯率查詢日期**,否則過幾天就失真。

### 11. 行前準備清單
用可勾選的清單形式:證件(護照效期、簽證、影本備份)、電壓與插座轉接、依查到的實際天氣給的衣物建議、常備藥品、當地付款方式準備(現金/信用卡/行動支付)、上網方案。

### 12. 實用資訊附錄
簽證與入境規定、時差、電壓與插座型式、通訊(SIM/eSIM/分享器)、貨幣與付款方式、基本當地用語。

### 13. 緊急頁
獨立成一塊,**要能單獨列印帶著走**:
- 當地報案與救護電話
- 鄰近行程地點的醫院
- 我國駐外館處與旅外國人急難救助電話
- 保險公司 24 小時服務電話
- 信用卡掛失電話
- 飯店電話與地址(**當地語言寫法**,方便直接拿給計程車司機看)
- 使用者提供的緊急聯絡人

## 撰寫細則

### 單一時間軸項目的完整範例

以下是**格式與資訊密度的示意**,說明一個時間軸項目「寫完整」是什麼樣子。**內容本身是舉例,實際排程時每一個欄位都必須實際查證**,不可以照抄這裡的店名、票價或時刻:

> **14:30–16:00** ｜ 室內 ｜ 白色戀人公園
> 北海道札幌市西區宮之澤 2-2-11-36 ｜ [Google Maps](https://www.google.com/maps/place/?q=place_id:XXXXXXXX)
> 當天營業時段:10:00–17:00(全年無休,最後入館 16:00)
> 門票:成人 ¥800,需事前線上預約指定時段,建議最晚出發前 3 天訂
> 交通:地鐵東西線 大通站 → 宮之澤站,約 17 分,¥290;3 號出口步行 7 分
> 雨天無影響(全程室內)

對照一下「寫不完整」會長什麼樣——這是要避免的:

> 下午 參觀白色戀人公園

差別不在文字多寡,而在**看完之後還需不需要自己再去查東西**。上面那份可以直接照著走,下面那份還要自己查地址、開放時間、門票、怎麼去、要不要預約。

### Google Maps 連結格式

每個景點/餐廳/飯店都要附連結,方便使用者或司機直接點擊導航:

- 透過 `places_search` 查到 `place_id` 時,用精準格式:
  `https://www.google.com/maps/place/?q=place_id:<place_id>`
- 沒有 `place_id` 時,用地點名稱與地址組成搜尋連結:
  `https://www.google.com/maps/search/?api=1&query=<地點名稱與地址,URL 編碼>`

## 排版與技術要求

- 用日期分頁籤或區塊區隔每一天,避免長篇條列文字堆疊
- 手機寬度可讀
- **可列印**:附 `@media print` 樣式。列印時日期分頁籤要全部展開,不能只印出當前那一頁
- **可離線**:出國後常常沒網路。地址、電話、營業時間都要以文字寫在頁面上,Google Maps 連結是額外便利,不是資訊本身的替代品

### 列印時展開分頁籤

日期分頁籤在螢幕上好用,但列印時如果只印出當前那一頁,整份手冊就廢了。分頁籤的實作要讓列印樣式能把全部日期展開:

```css
@media print {
  .day-tabs { display: none; }              /* 隱藏頁籤按鈕本身 */
  .day-panel { display: block !important; } /* 所有日期一律展開 */
  .day-panel { break-after: page; }         /* 每天各自一頁 */
  .emergency-page { break-before: page; }   /* 緊急頁獨立一頁,方便單獨撕下帶著 */
  a[href^="http"] { text-decoration: none; color: inherit; }
  /* 不要印出長網址:紙本上的 Google Maps 連結是無效資訊,
     地址與電話已經以文字寫在頁面上了 */
}
```

若用 JS 控制分頁籤切換,要確認**列印時不依賴 JS 狀態**(用 CSS 覆蓋 inline style,或監聽 `beforeprint` 先把全部面板展開)。


## 交付後的回覆

`present_files` 交付即可,**不需要在回覆中把整份行程再貼一次文字版**。可以簡短補充重點提醒,例如:哪些資訊目前還是預設值、哪幾項建議使用者盡快確認、訂位追蹤表裡最近的截止日是哪一項。
