# 資料查證與排程方法

其他參考檔處理的是「要問什麼」「要有什麼」「怎麼寫」「怎麼檢查」。這份檔案處理的是**資料要怎麼查證**,以及**排程本身的方法** —— 拿到問卷結果之後,一天的行程實際上要按什麼順序搭起來。

沒有固定順序的話,最常見的失敗是**先挑好想去的景點,再回頭發現時間對不上**,然後開始硬擠:砍交通時間、把用餐壓成 40 分鐘、假裝兩個相隔 40 分鐘車程的點可以連著走。從骨架開始排就不會走到那一步。

---

## 零、資料查證規則(排程之前)

**來源優先序** —— 同一項資訊在不同來源不一致時,取優先序高的:

1. 官方網站、官方訂位頁、官方公告
2. 官方社群帳號(常常比網站更新)
3. `places_search` / Google Maps 的營業時間
4. 大型評論平台(大眾點評、Tabelog、TripAdvisor)——人均消費用這類來源最合理,但要標明出處
5. 部落格與媒體報導——只當補充,不當唯一依據

**兩個來源明顯衝突時,不要自己挑一個就算了**,在文件裡標出來(「官網寫 11:00 開始,訂位平台寫 11:30,建議訂位時確認」)。

**時效** —— 看來源的日期。營業時間、票價、展期這類資訊,若來源超過一年,標註「資訊日期較舊,建議出發前確認」。整修閉館、疫後時段調整、季節性縮短都很常見。

**目的地本身資料稀少時** —— 小鎮、非熱門地區、當地語言沒有中英文資料的地方,查得到的餐廳與景點可能只有兩三個。這種情況要**明確告訴使用者查證的覆蓋程度**(「這個地區查得到具體資訊的餐廳只有 3 家,已全部排入;其餘時段建議抵達後由飯店協助推薦」),並據此調整密度期待。不要為了湊到「適中 4-5 項/天」而編出查不到的地點,也不要假裝資訊充足。可以主動建議使用者提供他知道的當地資訊,或改由當地飯店禮賓部補齊。

**查不到時的降級路徑**:`places_search` → `web_search` 店名+地址 → `web_search` 店名+官方網站 → **都查不到就換一個查得到的,不要放進行程**。放一個查不到的店然後標「待確認」,是把問題丟回給使用者,不是完成工作。

### 天氣:預報與歷史氣候不是同一件事

這一項很容易錯,而且錯了不會有人提醒:

- **行程在未來 10-14 天內** → `weather_fetch` 的預報有意義,直接用,並在行程裡標明是幾月幾日查的預報。
- **行程在更遠的未來**(一個月以上) → **預報沒有意義**,不要拿來當預報用。要改查該地該月份的**歷史氣候平均**(平均高低溫、降雨天數、濕度、日照),用 `web_search` 查,並在文件裡明確標示「這是該月份的歷史氣候平均,不是預報;出發前一週請再查實際預報」。
- 兩種情況都要據此給衣物建議與室內外備案,但**不要把歷史平均寫成預報**。

價格也同理:機票與飯店價格波動大,一律註明「查詢時價格」與查詢日期。

### 營業時間與休館日查核(硬規則,排入前逐項確認)

每一個景點、餐廳、店家、展館排進行程前,都必須確認**該項目在行程當天的那個星期幾是否營業、有沒有休館日或公休、當天的營業時段是否覆蓋你安排的時間**。週一休館、餐廳週三公休、神社/展館季節性縮短時段,是行程表最常見的實際事故,而且會直接毀掉那一天。

查證不到營業時間時,不可以當作營業;要在該項目旁明確標註「營業時間未能確認,建議出發前致電或由飯店禮賓部確認」,並同時附上一個已確認營業的備選。

**查到了、但跟行程衝突時更重要**:不可以默默把時間挪掉、把項目換掉或當作沒看到,要把矛盾明確寫出來交給使用者處理(例如「晚市 17:30 才開始,行程寫 17:00 入座 —— 請訂位時與餐廳確認」)。查核最有價值的產出就是這種矛盾,把它藏起來等於沒查。

## 一、先分配天,再排每一天

多天行程不要一天一天順著排下去,先做全局分配:

1. **扣掉抵達日與離開日的實際可用時間**(見第三節,這是最常被高估的地方)
2. **把固定錨點落到對應的日期上** —— 錨點在哪天,那天的主題就先被決定了
3. **依地理分區把區域分配到天** —— 同一天的項目盡量集中在同一個區域或同一條動線上。跨區來回跑是行程表最浪費時間的錯誤,而且在表面上看不出來(每一格都填滿了,但一半時間在車上)
4. **依天氣預報安排室內外** —— 查到的預報若某天有雨,把室內為主的那一天換到那天
5. **體力分佈** —— 最累的一天不要排在抵達日,也不要連續兩天都最累;返程日前一晚不要排到太晚

分配完之後才進入單日的排法。

## 二、排一天的六個步驟,順序不要換

### 步驟 1:錨點落位

當天的固定錨點先寫上去,連同它前後必要的緩衝。錨點是不能動的,所有其他東西繞著它排。

**錨點前面要留緩衝**,而且緩衝要對應風險:一般行程留 15-30 分;要排隊入場或核驗身份的留 30-60 分;會議或班機這種絕對不能誤的,再往前加。ref 那份行程把「17:30–18:00 準備登船」寫進時間軸,又在註解裡說「實際核驗建議留到 18:20–18:30,不要壓線」—— 這就是把緩衝寫進表裡而不是心裡。

### 步驟 2:用餐時段落位

依問卷的用餐時間偏好,把午餐與晚餐的時段先卡住。

**這一步一定要在挑景點之前。** 順序反過來的話,用餐時間會被景點擠壓成「14:20 吃午餐」或「40 分鐘吃完晚餐」這種實際上不合理的安排。先卡住用餐,景點自然只能放在剩下的區塊裡。

用餐時段長度的合理值:一般餐廳 60-90 分;需要訂位的正式餐廳 90-120 分;套餐制或包廂 120 分以上;米其林等級的品嚐菜單留 2-2.5 小時。**不要用 60 分鐘去排一家套餐制餐廳。**

### 步驟 3:確認當天的地理範圍

看一下錨點與餐廳的位置,決定這一天的活動範圍。接下來挑的景點都要落在這個範圍內,或落在往返路線上。

判準:任兩個相鄰項目之間的移動,**單程不要超過 30-40 分鐘**(除了進出機場、跨城移動這種必要的長程)。超過就要問自己是不是這一天塞了兩個不同區域。

### 步驟 4:填入主要項目

剩下的時間區塊,依步調密度填入景點與活動:

| 步調 | 每天項目數 | 說明 |
|---|---|---|
| 緊湊 | 5-6 項 | 不含移動行與用餐,是實際的活動項目數 |
| 適中 | 4-5 項 | |
| 悠閒 | 2-3 項 | 剩下的時間是真的空著,不是塞小活動 |

挑項目時同時看四件事:
- **當天營業/休館** —— 那一天營業,而且時段覆蓋你要放的時間(含最後入場時間,不是營業結束時間)
- **室內外比例** —— 對應問卷結果,以及當天的天氣預報
- **調性不要重複** —— 同一天不要排兩個同類型的大館、或連著兩個購物商場。ref 把大型博物館與單一媒材的小館排在一起,理由寫成「大館看規模與敘事,小館看單一媒材與光影」
- **停留時間要合理** —— 大型博物館 90-150 分、小型館 60-75 分、商場 80-140 分、觀景或拍照點 20-40 分。**不要用 30 分鐘排一座大型博物館**

### 步驟 5:插入移動行,然後驗算

每兩個項目之間插入一行移動,寫上實際查到的交通方式與時間。

然後**逐行驗算**:每一行的結束時間必須等於或早於下一行的開始時間。用手算過一遍,不要目測。對不上就回到步驟 4 調整項目或縮短停留,**不要縮短移動時間** —— 交通時間是外部現實,不是可以壓縮的變數。

車流量大的路段給區間並註明原因(例如「約 40–45 分,展期周邊車流量大」),不要給一個樂觀的單一數字。

### 步驟 6:收尾檢查

- 這一天的第一句定調寫了嗎(這天是輕鬆還是趕、唯一的硬時間是什麼)
- 有哪一段偏緊?寫出來,並指出延誤時從哪一段吸收
- 戶外項目有對應的備案嗎
- 包車的話,今天的用車時數有沒有超過司機可用時段
- 回飯店的時間有沒有超過問卷講的「最晚幾點回到飯店」
- **限制回核做了嗎**(飲食、無障礙、體力、保密、語言、價位)—— 見第二之二節

## 二之二、限制回核:問卷收集到的限制,每一項都要回頭核對

問卷花了好幾輪問飲食限制、無障礙需求、體力狀況、保密需求、語言支援 —— **排完之後一定要回頭逐項核對排入的項目真的滿足這些限制**,否則問了等於沒問。

這是很容易發生的失誤:問卷寫著「有人吃素」,行程卻排了一家海鮮名店;問卷寫著「需要無障礙安排」,行程卻排了一座要爬階梯的古蹟。問的時候很認真,排的時候忘了拿出來對。

| 問卷收集到的 | 排完之後要核對什麼 |
|---|---|
| 飲食限制(素食、宗教禁忌、過敏) | **每一餐**的餐廳都能滿足**全體**的限制。素食者要有能吃的主食,不是只有配菜。全團限制不同時,確認同一家店能同時滿足所有人;不能就換店或分餐 |
| 需要正式宴請規格 | 該餐廳有包廂、可訂位、能安排席次 |
| 需要無障礙安排 | 每個場地有電梯或斜坡、有無障礙廁所、路面沒有碎石與階梯、車輛能靠近入口。查不到要標註並建議事先致電確認 |
| 偏好較少步行 / 體力較弱 | 估算當天的**總步行量與連續站立時間**;需要久站的項目不要相鄰;每天要有實際坐著的時段(用餐以外) |
| 有年長者同行 | 休息點的密度夠;需要排隊的項目改成可預約的時段;避免久站 |
| 有嬰幼兒或兒童同行 | 場地有尿布台、有兒童餐、推車可否進入、活動年齡適宜、有午休時段 |
| 保密 / 低調需求 | 避開需要實名公開登記的活動、高曝光場所;文件裡不要寫可能外流的敏感內容 |
| 語言支援需求 | 優先選有中文或英文服務的店家與飯店;需要導覽的地方確認有無對應語言的場次 |
| 預算與價位接受度 | **每一項**都落在使用者說的區間內,而不是只有總計對得上 |
| 其他禁忌或務必避開的事項 | 逐項比對整份行程,包含備案章節 |

**核對結果要寫進文件,不要只在心裡對過。** 滿足限制的項目要看得出來(例如餐廳旁標「有素食套餐」、場地旁標「全程無台階、有電梯」),使用者才知道你確實考慮過;查不到的要標註並給下一步(「建議訂位時確認素食選項」)。

限制之間互相衝突時(例如「需要無障礙」但使用者又點名要去一個沒有無障礙設施的古蹟),把衝突攤開給使用者選,處理方式同 Step 2.5 的可行性檢查。

## 三、抵達日與離開日:最常被高估的兩天

**這兩天都不是完整的一天。** 把它們當成完整一天來排,是行程表最常見的結構性錯誤。

**抵達日的實際可用時間** = 落地時刻 + 入境通關(國際線 40-60 分,大型機場或旺季更久)+ 提領行李 + 前往市區的車程 + 飯店 check in。ref 那份行程 12:05 落地,寫了「12:05–13:05 入境」整整一小時,然後 13:05–14:00 進市區,實際上下午只剩三個多小時 —— 所以那天只排了同一棟建築裡的兩個項目。

抵達日還要考慮:
- 紅眼班機或長程飛行後,不要排需要體力或需要專注的項目
- 有時差的話,第一天不要排太晚,也不要排早起的第二天
- 飯店 check in 時間通常是 15:00 之後,更早抵達要考慮先寄放行李

**離開日的實際可用時間** = 起飛時刻往回推:國際線建議 2.5-3 小時前抵達機場、國內線 1.5-2 小時,再往回推前往機場的車程(給塞車緩衝),再往回推退房。ref 的離開日只有 09:00–10:00 一個小時的活動,並且明確寫出「10:00 一定要離開,車程約 50 分,最晚 11:00 前抵達機場」。

離開日的活動要選**可以隨時中斷的**(散步、飯店設施、機場周邊逛街),不要排需要完整時段的項目(套餐餐廳、需預約的導覽、大型展館)。

## 四、常見的排錯

| 錯法 | 為什麼錯 | 正確做法 |
|---|---|---|
| 先挑景點再算交通 | 算出來對不上,只能硬擠 | 錨點與用餐先落位,景點填剩下的區塊 |
| 一天跨兩三個區域 | 每格都填滿,但一半時間在車上,表面看不出來 | 步驟 3 先確認地理範圍 |
| 用「營業到 17:00」當可停留到 17:00 | 多數館有最後入場時間,通常早 30-60 分 | 查最後入場時間,不是營業結束時間 |
| 用餐被壓成 40 分鐘 | 套餐制或需訂位的餐廳根本吃不完 | 步驟 2 先卡用餐時段,並依餐廳類型給長度 |
| 抵達日排滿 | 入境通關與進市區會吃掉半天 | 見第三節 |
| 錨點前沒留緩衝 | 一延誤就直接誤掉不能誤的事 | 步驟 1 依風險留 15-60 分 |
| 密度不足就寫「保留彈性時間」 | 這是偷懶的說法,不是行程 | 補實際項目;真的要留空,寫清楚這段空白的用途(回飯店休息、自由購物、體力緩衝) |
| 縮短交通時間來讓表對上 | 交通時間是外部現實 | 改項目或縮短停留,不要動交通 |
| 兩個同類型大館排同一天 | 會過載,而且下午那個看不進去 | 調性互補,大館配小館 |

## 五、密度不足時怎麼補

驗算完發現某天只有 3 項而使用者選的是「適中」(4-5 項),要補。補的順序:

1. **先看同一區域還有什麼** —— 已經在那附近、不用增加交通時間的項目最划算
2. **用餐前後的短項目** —— 咖啡、甜點、書店、觀景點,20-40 分鐘的填補
3. **延長現有項目的停留** —— 如果原本給的時間偏短(例如大館只給 60 分),延長比新增項目自然
4. **飯店設施** —— 水療、泳池、下午茶,尤其適合放在體力已經耗掉的傍晚

不要為了湊數把遠處的項目硬拉進來,那會把交通時間變成當天的主體。

## 六、跨城市或跨區域移動的那一天

移動日要當成「半天 + 移動 + 半天」來排,不是「一整天扣掉移動」:

- 移動前那一段要留退房與到站的緩衝
- 移動本身要寫清楚是什麼交通工具、幾點到幾點、票價、是否需要事先訂位(高鐵/新幹線的指定席、渡輪班次)
- 行李怎麼處理(隨身、寄放、宅配到下一間飯店)——這件事常常被忽略,但拉著行李逛街會毀掉半天
- 到站之後那一段,第一件事通常是放行李,不要一下車就排景點
